Managing Linux Users & Groups

Foundations of System Security and Access Control

The Core Files

User and group management is the foundation of system security in Linux. It forms a critical component of the AAA (Authentication, Authorization, Accounting) framework, enforcing the Principle of Least Privilege. At a technical level, all user and group data is stored in plain text files within the /etc directory. Hover over (or tap) the cards below to explore them.

Privilege Escalation: The sudo Command

Logging in as the root user is generally discouraged due to security risks. Instead, administrators use sudo (Superuser DO) to execute commands with elevated privileges on a temporary, per-command basis.

How it works

When a user prefixes a command with sudo, they are typically prompted for their own password, not the root password. The command is then logged, providing an audit trail of administrative actions.

The /etc/sudoers file

Permissions for who can use sudo are defined in the /etc/sudoers file. Never edit this file directly with standard editors like nano or vim. Always use the visudo command, which performs syntax checking before saving, preventing accidental lockouts.

terminal - visudo

# Common entries in /etc/sudoers

root ALL=(ALL:ALL) ALL

# User privilege specification (allows root to run any command anywhere)

%admin ALL=(ALL) ALL

# Members of the admin group may gain root privileges

%sudo ALL=(ALL:ALL) ALL

# Allow members of group sudo to execute any command

bob ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

# Allows user 'bob' to restart the nginx service without entering a password.

User Administration & Modification

The primary commands for managing human users (UID 1000+) are useradd, usermod, chage, and userdel.

  • ●
    Creation: useradd -m username sets up the new account and creates the home directory (-m) by pulling default profile files from /etc/skel.
  • ●
    Modification (usermod): Modifies existing account properties.
    • -l newname oldname: Change login name.
    • -L / -U: Lock / Unlock a user account (places a '!' in the shadow file).
    • -s /path/to/shell: Change default login shell.
    • Critical rule for groups: When adding a user to a secondary group, you must use the append flag (-a) alongside the group flag (-G). If you run usermod -G developers bob, Bob is removed from all other secondary groups! Always use usermod -aG.
  • ●
    Password Aging (chage): Modifies password expiry information stored in /etc/shadow.

    Example: chage -d 0 username forces the user to change their password on the next login.

  • ●
    Deletion: userdel username deletes the user entry. To securely clean up, use userdel -r username to also remove their home directory and mail spool.

Group Management & Modification

Groups allow administrators to grant access to files and directories in a scalable way. Instead of applying permissions to fifty individual users, you assign permissions to one group, and add those fifty users to it.

Primary Group

Every user must have exactly one primary group. In most Linux distributions, a primary group is created automatically with the same name as the new user. Files created by the user default to this group's ownership.

Secondary Groups

Users can belong to multiple secondary (supplementary) groups concurrently (e.g., wheel for sudo access, or www-data for web files). Verify memberships using the groups or id commands.

Creating, modifying, and deleting groups relies on groupadd, groupmod, and groupdel.

  • ● Creation: groupadd groupname creates a new group. Use -g GID to specify a custom Group ID.
  • ● Modification: groupmod -n new_name old_name renames a group. You can also change a group's GID with -g.
  • ● Deletion: groupdel groupname deletes the group. Note: You cannot delete a group if it is currently assigned as the primary group for any user.
