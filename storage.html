The Storage Stack

Linux organizes storage in a hierarchical stack. It's helpful to think of it from the hardware up:

  • Physical Disk: The hardware device (e.g., `/dev/nvme0n1`).
  • Partition: Logical divisions of that disk (e.g., `/dev/nvme0n1p1`).
  • Filesystem: The logic that handles data storage (e.g., `ext4`, `XFS`).
  • Mount Point: The directory where the filesystem is attached (e.g., `/var`).
Why this matters: Proper organization prevents a single full partition (like a log directory) from crashing the entire system.

Filesystems & Quotas

A filesystem is the data structure used to control how data is stored and retrieved.

Common Types:

  • Ext4: The reliable Linux standard. Versatile.
  • XFS: High performance, great for large files and 64-bit systems.
  • Btrfs: "Better FS." Supports snapshots and pooling.

Quotas & Encryption:

  • Quotas: Restrict disk space or file counts per user or group.
  • LUKS: The standard for disk encryption in Linux (Linux Unified Key Setup).
Why this matters: Choosing XFS for a database or Btrfs for a backup server can drastically improve reliability and efficiency.

RAID Fundamentals

Redundant Array of Independent Disks combines multiple physical disks into a single logical unit for redundancy or performance.

RAID 0 (Striping)

Splits data across disks. Fast performance, zero redundancy. If one disk fails, all data is lost.

RAID 1 (Mirroring)

Duplicates data on two disks. High redundancy, but you lose 50% of your total capacity.

RAID 5 (Parity)

Stripes data and parity information across 3+ disks. Can survive 1 disk failure. Balanced.
