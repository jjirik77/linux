Section 1

Virtualization Fundamentals & Hypervisors

Virtualization abstracts physical hardware resources (CPU, RAM, Storage, Network) to create independent virtual operating environments. The underlying manager is the Hypervisor or Virtual Machine Monitor (VMM), a concept pioneered historically by IBM mainframes.

Exam Focus

Be prepared to identify hypervisor classifications (Type 1 bare-metal vs Type 2 hosted), recognize standard disk image extensions like .vmdk, .vdi, and distinguish between OVF (directory format) and OVA (archived single file).

Section 2

Virtual Networking & libvirt / virsh Management

Linux virtualization relies heavily on libvirt as an API abstraction daemon to manage hypervisors like KVM and QEMU. The standard administrator command-line tool is virsh.

Essential virsh Command Reference Exam Critical
virsh list --all# Lists all virtual machines (running and inactive domains) on the host.
virsh start <vm-name># Boots up a stopped virtual machine instance.
virsh suspend / resume <vm># Pauses guest execution in memory or resumes execution.
virsh migrate --live <vm> qemu+ssh://dest/system# Live migrates a running VM across physical hypervisors without service interruption.

Section 3

Cloud BLOB Storage Classifications

Cloud architectures leverage BLOB (Binary Large Object) storage to manage unstructured data accessible via standard HTTP/HTTPS REST endpoints. CompTIA Linux+ tests your precise distinction between the three standard BLOB types:

BLOB Type Architecture & Constraints Primary Use Case
Block BLOB Max 100MB per block, up to 50,000 blocks. Requires explicit commit. Uncommitted blocks expire in ~7 days. Streaming media, large file archives.
Append BLOB Optimized for append-only operations. Existing blocks cannot be modified or reordered. Centralized log aggregation, audit tracking.
Page BLOB Structured in 512-byte pages. Supports random read/write access up to ~8 TB capacity. Virtual machine hard disk images (.vhd), databases.

Container Engine (Docker / Podman)
Shared Host OS Kernel & Hardware

Containers virtualize at the OS application level, sharing the host kernel directly. This provides lightning-fast startup and extreme efficiency.

Pod

The smallest deployable unit in Kubernetes. Encapsulates one or more tightly coupled containers sharing network namespaces and storage.

Sidecar Container

A secondary helper container attached to a primary pod container to handle auxiliary tasks like log shipping or proxying.

Deployment

Controller object managing pod replica sets, ensuring self-healing, scaling, and rolling updates across cluster worker nodes.

Section 6

OS Automation: Kickstart & cloud-init

Kickstart (Anaconda Installer)

Automates Red Hat-class enterprise installations without manual interaction.

  • Generates default /root/anaconda-ks.cfg after install.
  • Validated via ksvalidator before production rollout.
  • Kernel boot parameter inst.ks= points installer to configuration source.
  • Network PXE boots require ip=dhcp and inst.repo= parameters.

cloud-init Instance Initialization

Industry-standard bootstrap facility for cross-platform cloud virtual machines.

  • Handles first-boot configurations (SSH keys, hostnames, users).
  • Crucial configuration file path to memorize for the exam:
/etc/cloud/cloud.cfg
