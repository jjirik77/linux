01. Learn: Core Topics

The 3 Permission Tiers

Owner (u): User account that owns the node.
Group (g): All users in the assigned group.
Others (o): Everyone else with a shell on the system.
File vs. Directory:

x on a file runs it. On a directory, x allows entering (cd) or accessing files within it!

# ls -l snapshot
-rwxr-xr--
rwx (7) : Owner has Read (4) + Write (2) + Exec (1)
r-x (5) : Group has Read (4) + Exec (1)
r-- (4) : Others have Read (4) only

SUID (4000)

u+s

Executes with owner permissions (e.g. /usr/bin/passwd). Shown as 's' in User slot.

SGID (2000)

g+s

New files in directory inherit parent group. Shown as 's' in Group slot.

Sticky Bit (1000)

+t

Only file owner or root can delete (used on /tmp). Shown as 't' in Others slot.

Exam Note: Capital S or T = Missing underlying x bit (error / non-executable)! -rwsr-xr-x

The Base Permission Rule

• New Files base: 666 (rw-rw-rw-, no execution)
• New Directories base: 777 (rwxrwxrwx)

The system subtracts the current umask to determine effective mode.

# Standard Default: umask 022
Files: 666 - 022 = 644 (-rw-r--r--)
Dirs: 777 - 022 = 755 (drwxr-xr-x)
# Secure Default: umask 027
Files: 666 - 027 = 640 (-rw-r-----)
Dirs: 777 - 027 = 750 (drwxr-x---)

Ownership & Attributes

• chown user:group file : Change owner & group (-R recursive)
• chgrp group file : Change group ownership only
• chattr +i file : Immutable (cannot delete or edit even as root!)
• chattr +a file : Append-only (ideal for audit logs)
# POSIX Access Control Lists (ACLs)
$ getfacl document.pdf
# Grant maria read-write access:
$ setfacl -m u:maria:rw document.pdf
Notice the '+' symbol: -rw-rw-r--+
